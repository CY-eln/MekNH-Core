# 输出空间预留与暂停生产

## 行为

- 机器逻辑先给出受机器等级、原料数量等限制的并行上限；开工时再按全部产物的剩余可装容量选择不超过上限的最大可行份数。上限4但只能装2份时启动2份；只够1份就启动1份，连1份都放不下才暂停。普通机与通用多方块共用limitParallelByOutputs，保持原有逐级回退语义，不把最大并行数当成必须满足的固定值。
- 每次检查复制当前实际输出库存/储罐，在同一份影子上逐项插入，要求所有产物都能完整装下；不修改实际输出，不抽随机数。
- 概率产物按最大可能量预留，不使用概率期望值；数量乘法用long，超出现有真实产出int接口可表示的总量拒绝，而不是溢出后误判能放下。
- 开工前输出不足：不开始批次，不扣原料，不耗能。开工选择使用机器给定上限与输出可容纳份数，不要求输出一定容纳机器最大并行数。
- 已在生产的批次输出不足：保留配方、批次数和进度；在消耗本tick能量/蒸汽前停止推进。每tick复检，恢复空间后自动继续，不重复扣原料。已扣的原料属于该批次，不因暂停返还或再次扣除。
- 未完成批次不拆分提交，不因为只腾出部分空间就丢弃剩余产物。
- 土高炉/焦炉使用各自的真实库存副本，输出受阻不再清零进度；原料不匹配/结构失效仍按原规则处理。
- 多方块输出仓按实际顺序组合，流体与化学品共用MEK仓时保持互斥，不把一仓当两仓使用。

## 警告

- 普通机器沿用现有输出警告位与主线文案，即使当前批次已经扣完输入也仍可显示。此PR不更改任何GUI、菜单或语言文件。
- 土高炉/焦炉仅接入服务端受阻状态与暂停恢复，不包含新增ContainerData字段、GUI感叹号、tooltip或语言文件。通用多方块沿用右键状态信息展示现有警告。
- 警告由服务端判定；客户端只显示，不能决定扣料、产出或推进进度。

## 存档

未改真实库存NBT和原有配方/进度/并行字段，不新增持久占位物品。预留是瞬时副本，每次重新检查；暂停后的旧存档加载由原恢复批次逻辑恢复，再检查输出空间。此PR不新增菜单同步值。

## 开发验证

```bat
gradlew.bat --no-daemon -I devtools/output-reservation-probe.init.gradle classes outputReservationProbe --offline --no-configuration-cache
```

OutputReservationProbe使用真实配方、物品handler和fluid/chemical罐的独立JVM检查，不是世界或完整BE tick集成测试。覆盖多产物竞争、累计超容量、部分接受拒绝、概率最大值、倍数溢出、共享MEK仓、validator与真实库存不变。

仍需IDEA实机验收：开工前堵输出不扣料不耗能；生产到一半堵输出后进度冻结且警告出现；取走产物恢复原进度；电力/蒸汽均测；阻塞状态区块卸载/重进恢复；多产物数量无丢失、无复制。未声称这些实机行为已经测试。

## 本轮检查结果与已知探针限制

- 源码classes编译通过；outputReservationProbe的78项真实配方/存储离线检查通过（含chemical与共享MEK仓）。
- 额外执行历史machineProbe并未全通过，报告六项：vanilla_smelting模板没有解析后的显式outputs，coke_oven属于多方块却只扫描普通machine定义；三项dust产物为离线未注册的Mekanism物品；snowball的water输出没有历史ProbeOutput流体存储（固定返回0，新的snapshot也无罐）。
- 这些失败按旧的canProduce与既有探针输入筛选逻辑也可静态推导；本轮没有动态回切旧实现运行baseline，不能将全库machineProbe报告成通过。未改无关配方或放宽断言以掩盖失败。
- 78项不包含完整世界中的BE能耗/进度/GUI交互测试；上面的IDEA验收项仍待实机执行。

## 范围外

不做新的机器并行等级规则、不做独立多罐/通用GUI自动排版、不改原料重复谓词计数逻辑，不提供默认土高炉配方、不打包JAR。本PR仅产物产出方案；所有Screen、Menu、语言、GUI原型与贴图修改均不纳入。
